# Capa 5: servidor MCP "Ask the court" — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local stdio MCP server (`ventaja mcp serve`) exposing six read-only tools and a glossary resource over the packaged artifacts, with a CLI twin (`ventaja mcp call`) so every tool is testable without an AI client.

**Architecture:** A pure service layer (`ventaja/mcp/service.py`, `AskService`) answers every tool from the packaged tables (decisions, curve summaries, player/team cards, frames, roster, the new `games.parquet`) and reuses `Board` for `what_if`; it never imports `mcp`. A thin `ventaja/mcp/server.py` registers the tools on `MCPServer` (MCP SDK 2.x), maps `VentajaError` to `ToolError`, and serves the glossary. `ventaja/cli/mcp.py` runs the server or calls one tool and prints its JSON.

**Tech Stack:** Python ≥ 3.12, uv, pydantic v2, polars, typer, `mcp>=2.3` (runtime dep; `MCPServer` from `mcp.server.mcpserver`, `Client` from `mcp.client` for in-memory tests), pytest, ruff, mypy strict.

**Spec:** `docs/superpowers/specs/2026-11-03-capa-5-mcp-design.md` (parent: `docs/superpowers/specs/2026-11-01-ventaja-design.md`).

## Global Constraints

- Code, docstrings, tool names, tool descriptions, field names and every string a tool returns: English. ADR and this plan: Spanish allowed only in ADR/docs.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy` (strict) and `uv run pytest` (`-W error` clean) pass after every task.
- Conventional commits (`feat:`, `test:`, `docs:`, `chore:`) ending with the two attribution lines the session provides.
- No API key, env var or download needed to start the server: everything reads through `artifact_dir` (build if present, else packaged `artifacts/`), exactly like `Board`.
- `decide_snapshot` (via `Board`) is the only valuation entry point; no geometry or valuation is re-implemented.
- New constants only in `src/ventaja/value/params.py`: `MCP_DEFAULT_LIMIT = 10`, `MCP_MAX_LIMIT = 50`.
- Every float a tool returns is rounded to 3 decimals; every player/team id travels with its name.
- Ambiguous or empty name lookups fail with a message listing the candidates (`id — name — team`); never pick for the user.
- README stays ≤ 1000 words and 2 figures (currently 987 and 2).
- `ventaja mcp` subcommands use lazy imports of `mcp`/`ventaja.mcp.server` (CLI start-up stays fast, as `board` does).

## Review Focus

1. A name query that matches several people (e.g. `"Garcia"`) must raise an error listing every candidate; the tool must never answer about the first match. → test in Task 2.
2. `clock` combined with `by` other than `mean_cost`, and `limit` outside `[1, MCP_MAX_LIMIT]`, must be rejected with a message naming the rule, not silently reinterpreted. → tests in Task 2 (service) and Task 5 (server schema).
3. `what_if` moving a player who is not one of the ten on the frame, or with non-finite coordinates, must fail with the ten names / a validation error, and coordinates outside the half court are clamped and reported. → tests in Task 4.
4. `explain_shot` / `what_if` on an excluded shot or an unknown id must fail with a message naming the shot and the reason, not a stack trace. → tests in Task 3 and Task 4.
5. A shot with unknown shot clock must not enter any `clock` band, and a shot without a curve summary must come back with `verdict = null`, `headline = null` rather than being dropped. → tests in Task 3.

Excludes `LEAGUE_ID`; with `clock`, filters `clock_{band}_n >= min_shots` and sorts by `clock_{band}_cost` desc; else filters `n_shots >= min_shots` and sorts by `by` desc; ties: `n_shots` desc, `player_id` asc; nulls last. `league` = the LIGA row's metrics (with the band when `clock`).
    - `def player_profile(self, player: str) -> PlayerProfile` — `resolve_player` then `card_of`; `phrase` = `phrase_en`; `clock` has one `ClockBand` per band; `alternatives` one per `ALT_TYPES`.
    - `def _round(x: float | None) -> float | None` (3 decimals) used for every float field.
